## 安装与使用

1. 解压整个压缩包，保留 `models`、`vendor` 等文件夹。
2. 在 Microsoft Edge 地址栏输入 `edge://extensions`，打开“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择**直接包含 `manifest.json` 的文件夹**。
4. 打开一个普通 HTTP / HTTPS 视频网页，播放视频，点击工具栏中的“清声”。
5. 在 B 站普通视频页，点击“后台处理 B 站（原声继续播放）”，允许访问视频 CDN；扩展会创建后台处理页并自动开始，原网页保持在前台。
6. 点击“查看处理进度 / 保存音轨”打开处理页。进度到 100% 后，先暂停原视频，再播放分离结果或保存音轨。
7. 关闭播放页会释放处理结果；回到 B 站可手动继续原视频。若使用其他网站，请使用下述实时捕获模式。

无需安装 Node.js、Python、FFmpeg 或本地模型服务。模型与推理运行库已包含在文件夹内，正常使用无需联网下载它们。扩展不会自动加载到你的 Edge，也没有发布到扩展商店。

建议使用较新版本的桌面 Edge。本扩展基于 Chromium 116+ 的捕获架构；GPU 兼容性仍取决于浏览器版本、显卡和驱动。Edge 的图形加速开启且 WebGPU 可用时，会优先尝试 GPU；部分算子仍可能在 CPU 执行。

## 保存音轨用于剪辑

在独立处理页等待进度到 100%，点击“保存人声 WAV”或“保存伴奏 WAV”。文件是 44.1 kHz、立体声、16 位 PCM WAV，时长与处理音轨一致；可导入常用剪辑软件。导出为原始分离结果，不受人声、伴奏和总音量滑块影响。两种音轨分别保存，不含画面。实时捕获模式暂不提供完整音轨保存。

## B 站预处理模式

- 适用于普通 `/video/BV...` 视频页，不适用于直播、番剧、课程或受保护流。先在 B 站正常播放几秒再打开插件，有助于页面提供音轨信息。
- 扩展读取页面已有的播放地址，不调用账户接口，也不读取 Cookie 值。音轨在本机浏览器内解码和分离。
- 音轨全部处理后才开放播放；播放时无需继续 AI 推理，因此不再有固定的 12–30 秒音频延迟。实际设备与浏览器输出延迟仍然存在，同步目标并非保证零毫秒。
- 音量调整直接作用于已处理音轨；暂停和跳转以画面时间为准重新定位声音。若改变播放倍率，音频也会改变倍率，暂未实现保音调变速。
- 当前上限为 10 分钟、100 MB 压缩音轨、单声道或立体声，避免解码与分离占用过多内存。原声、人声以及模型在处理阶段会占用较多内存。
- 原网页播放状态和音量保持不变。处理完成后不会自动抢占播放；要试听分离结果，请先手动暂停原 B 站视频，避免双重声音。处理后视频在插件自己的播放页播放，优先 720p H.264；不改变或增强画面。画面仍从 B 站 CDN 加载，需要网络。加载完成的音轨不会写入磁盘。
- 第一次播放前必须等待模型处理。CPU 可能需要超过视频本身时长的等待；进度条会在第一个片段完成后估算剩余时间。
- 关闭页面后结果不保留，再次打开需要重做。B 站页面结构、地址时效或 CDN 限制可能导致读取失败；发生错误时请刷新原视频页后重新打开。
- 已增加源码、时间线与播放器状态测试，**尚未完成真实 B 站页面与 Edge 的端到端测试**。

## 实时捕获模式

打开扩展面板后会自动准备 AI 模型，等待就绪，再点击“开始处理此标签页”。默认播放原声，AI 就绪后由你手动切换。关闭面板不会中断模型准备；已加载的模型会复用。在面板内点击停止后不会自动重启，重新打开面板时才会再次准备。此模式用于不能提前读取音轨的网页：

| 项目 | 当前行为 |
| --- | --- |
| 人声控制 | Demucs AI 预测人声，不是频段均衡器；范围 0–200% |
| 伴奏控制 | 原始信号减去 AI 人声作为伴奏；范围 0–200% |
| 总音量 | 0–100%，默认 80%，含平滑增益和过载保护 |
| 处理范围 | 当前标签页内的全部声音；同时仅支持一个标签页 |
| 缓冲 | 可选 12 / 20 / 30 秒，默认 20 秒，运行中不能更改 |
| 关闭控制面板 | 音频继续处理；重新打开面板可恢复控制 |
| 网页刷新 / 新页面导航 / 关闭标签页 | 停止处理，避免上一页面的缓冲声音串入新页面 |
| 暂停 / 跳转进度 | 可检测的主视频暂停或跳转时静音输出；恢复播放后仍有实时缓冲延迟。跨域嵌入播放器可能无法检测 |
| 硬件跟不上 | 有界缓存，丢弃过期结果，自动切回当前原声；需手动再次切换 AI |
| DRM / 受保护内容 | 不绕过保护，可能无法捕获或只有静音 |

默认直接播放原声，AI 在后台缓冲，不再先静音等待。准备好后点击“切换到 AI 音频”。**仅 AI 模式的声音落后画面所选缓冲秒数，另加设备开销，不支持口型同步。** 可随时切回原声。

原声模式下，人声与伴奏滑块暂不生效；总音量仍有效。AI 覆盖率可在“处理状态与使用说明”中查看。延长缓冲只能吸收偶发延迟，不能解决长期推理速度低于实时的问题。

模型主要面向音乐中的歌唱人声，对对白、混响、多人重叠及特效声的分离效果不保证；人声和伴奏之间可能有残留或伪影。“0%”表示把对应预测声部静音，不保证语义上的所有人声都完全消失。

## 性能与验证

模型每次处理 7.8 秒 / 343,980 采样点的立体声音频，采样率 44.1 kHz。相邻窗口重叠 25%，每约 5.85 秒需要完成一次推理。

- 本环境单线程 WASM / CPU 测试：模型加载约 1.04 秒，单次推理约 14.75 秒。
- 连续处理速度按 `5.85 / 推理秒数` 计算，上述结果约 **0.40×，不满足连续实时分离**。
- 上述测试使用合成信号验证真实模型流程、尺寸及数值，**不是分离音质评测**。
- GPU 速度及 Edge 的实际音频捕获、GPU 回退、口型差异和长时间稳定性尚未实测。
- 20 项自动测试通过：包含实时音频混合与资源管理、捕获配置与失败重试、预处理窗口覆盖与取消、播放时钟同步、B 站地址验证以及临时请求规则清理。
- 模型 SHA-256 校验、模块引用、必需资源和 Manifest 检查通过。

## 架构

预处理路径：`popup → preplay/service.js → preplay.html → preplay/page.js → preplay/worker.js → audio/preprocess.js → audio/separator.js`。处理完成后由 `preplay/mixer.js` 按视频时钟播放缓存音轨。来源读取、模型计算、音量混合和页面 UI 各自独立。

```text
popup.html / src/ui/popup.js
    │ 控制消息、状态查询
src/background.js                ← 权限、捕获授权、命令串行化、标签页生命周期
    │
offscreen.html / audio/offscreen.js ← 持有音频流与模型线程，面板关闭仍可工作
    ├── AudioWorklet / processor.js ← 捕获、时间线、固定延迟、独立音量、实际输出
    │       └── timeline.js         ← 有界环形缓存、预测重叠、原声回退
    └── Worker / worker.js          ← 分块与调度
            └── separator.js       ← 模型适配、归一化、ONNX 推理与人声重建
                    └── vendor + models
```

设计要点：

- `settings.js` 是统一参数校验入口，防止无效值进入音频线程。
- 主线程不运行模型；推理线程与音频输出线程分离。
- 背景 Service Worker 不是音频资源的持有者，休眠不应该中断播放。
- 输入采用单个在途消息和约两个模型窗口的有界等待队列，避免同步 WASM 推理造成消息无限积压。
- 预测按绝对采样序号定位，跳过已经播放的数据；缓冲时长不会因算力不足无限增长。
- 预测写入分散到多个音频回调中，避免一次复制数十万样本阻塞音频线程。
- `伴奏 = 原始混音 - AI 人声`；两路增益均为 1 时，限幅前精确重建原始混音，保留立体声。
- 15 ms 增益平滑减少拖动滑块产生的突变；无前瞻软限幅避免严重数字削波，过载时仍可能产生失真。
- 异常和停止都会关闭流、音频上下文及模型线程。停止后模型需要重新准备，这是为了释放内存。

## 隐私与权限

- `activeTab`：用户主动打开扩展后访问当前标签页的信息。
- `tabCapture`：捕获选中标签页的声音，不读取麦克风。
- `offscreen`：在面板关闭后继续音频处理。
- `storage`：保存音量 / 缓冲设置，以及预处理会话所需的临时媒体地址。
- `scripting`：主动启动预处理时只读取当前播放信息；实时模式中监听主视频暂停 / 恢复事件以控制输出，不改变网页播放器的播放状态或音量。
- 可选 `*.bilivideo.com / .cn / .net`：第一次使用 B 站预处理时由浏览器询问，用于读取音轨和播放画面；实时捕获模式无需这些权限。
- `declarativeNetRequestWithHostAccess`：只为本扩展自身发出的 B 站 CDN 请求设置来源头；不改动原网页或其他网站请求，关闭预处理播放页后移除规则。

不申请所有网站的读取权限，不上传或保存用户音频文件，不加载远程代码。预处理会话的媒体地址暂存在浏览器会话存储中，播放页关闭后清理；音频数据仅在内存中。CSP 仅允许自身资源与指定 B 站 CDN 的媒体请求。实时模式可能显示浏览器的“正在共享 / 捕获标签页”提示。

## Edge 手动验收清单

1. 加载后扩展管理页无错误，面板可显示“AI 已就绪”。
2. 普通公开视频网页启用后有缓冲倒计时，随后能听到声音；系统只出现一份声音。
3. “只听人声”“只听伴奏”效果可区分，总音量 0% 能静音；观察 AI 覆盖率以排除原声回退。
4. 关闭面板后继续播放，重新打开后滑块及状态一致。
5. 停止后立即恢复网页原声，释放捕获提示；刷新或关闭标签页也正确停止。
6. 打开另一标签页，显示另一标签页正在处理，不能意外覆盖现有会话。
7. 重复准备 / 启动 / 停止，检查无重复播放；测试暂停、进度跳转、设备切换与 GPU 不可用场景。
8. 连续播放至少 10 分钟，检查内存、AI 覆盖率与性能是否可接受。
